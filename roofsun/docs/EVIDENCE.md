# 模型数据从哪里来，是否足以支撑结论？

2026-10-03 核对，基于 Jim RoofSun 2.1.0。运行时固定 pvlib 0.15.2；在线 stable 文档会更新，因此复现以依赖锁和保存的输入为准。

## 总体判断

数据足以支持比赛所要求的、条件透明的工程决策原型。它不只是界面动画：能量与现金流由代码计算，已知关系与参考案例可复现。但还没有足够证据保证某户天台的真实发电量或回本年月。

**模型验证、现场验证、用户验证是三件事。**前者已有基准与参考流程；后两者尚未完成。比赛题目允许用已知关系或参考案例检验模型，不强制取得用户访谈或建造实体系统。不编造用户记录，也不把未访谈误写成“不符合题目”。

## 来源清单与实际用途

| 数据/研究/规则 | 链接与已接入内容 | 适用边界 |
|---|---|---|
| NASA POWER | [Hourly API](https://power.larc.nasa.gov/docs/services/api/temporal/hourly/)；`data/weather_2023.csv`、2024、2025 以及各年 metadata | 一处参考网格的 GHI 和气温，不是每个屋顶的传感器。2024 为 8784 小时；UTC 年数据转换到香港时区，不完全等于香港本地历年 |
| 香港天文台 | [2025 年度报告表 2b](https://www.hko.gov.hk/en/wxinfo/pastwx/2025/ywx2025.htm)；`data/hko_reference.json` 保存月均日太阳辐射 | 京士柏站与 NASA 网格不同；核对气象输入量级，不校准屋顶发电。尚未接入 2023/2024 同年站点观测 |
| Reda, I.; Andreas, A. | [Solar Position Algorithm for Solar Radiation Applications，NREL/TP-560-34302，修订报告](https://docs.nlr.gov/docs/fy08osti/34302.pdf) | 对照论文报告的太阳位置案例，不等于验证整套发电、安装成本和收益 |
| pvlib 遮挡几何 | [shaded_fraction1d](https://pvlib-python.readthedocs.io/en/stable/reference/generated/pvlib.shading.shaded_fraction1d.html) | 与自建光线/平面关系进行 25 案例核对，属于实现一致性。有限排长、物件中心采样和真实电损仍有近似 |
| pvlib ModelChain / PVWatts | [官方参考流程](https://pvlib-python.readthedocs.io/en/stable/reference/generated/pvlib.modelchain.ModelChain.with_pvwatts.html) | 无遮挡单排、相同容量/天气/朝向，比较三种倾角的全年和月度结果；共用部分组件，不能称完全独立实测 |
| 香港机电署 | [2026-07-10 上网电价 FAQ](https://re.emsd.gov.hk/tc_chi/fit/faq/files/260710_FAQ_FIT%20(TC).pdf)；`data/settings.json` | 电价、年期与部分初步约束。未计算抗风、支承连接、点荷载等，不构成结构认可或完整法规审批 |
| 中电 | [上网电价调整说明](https://www.clp.com.hk/zh/feed-in-tariff-rate-adjustment) | 核对相应申请费率口径。真实申请需匹配供电公司、申请时间及实际资格，不凭模拟结果确认资格 |

项目调用的是 API、读取官方表格、复用公开算法。没有训练自有 AI 模型，也没有下载论文中全部原始实验并重新拟合。NASA 原始请求 URL、时间基准与单位保留在 metadata；验证报告包含代码及输入文件指纹。

## 目前仍是假设的内容

- 450 W 面板的尺寸、重量、温度系数、NOCT、支架重量和年衰减是通用工程参考，不是某品牌校准。
- 0.85 系统係数和 0.2 反照率简化损失与地面反射。
- 默认 HK$25,000/kW 加 HK$5,000、维护与逆变器更换费用是假设，不是取得的安装报价。
- 2033 年后自用比例及避免购买电价是情景输入，不是未来电价预测。
- −15% 发电压力测试不是统计置信区间；三年天气也不能单独证明未来 P90 产出。

这些假设已标明，足以做“如果条件如此，会怎样”的实验。真实报价或商业面板数据能改善个别物业的判断，但不为使原型看起来完整而杜撰。

## 非物理背景的人可以这样理解

### 1. 发多少电

```
某小时发电量 ≈ 面板数 × 单板额定功率 × 面板实际收到的日照/标准日照
               × 温度修正 × 系统系数 × 1 小时
全年发电量 = 每小时发电量相加
```

GHI 先分解成直射与散射，再换算到倾斜面；周围天际线、排间遮挡与物件近似影响实际收到的光。不能简单用“有太阳的小时数 × 额定功率”代替。

### 2. 何时回本

```
累计现金结余 = −初始安装费 + 累计收入 − 累计维护及更换费
NPV = −初始安装费 + Σ(每期净现金流 / (1+折现率)^距今天数对应年数)
```

首次回本是第一次非负；持续回本还要看后续费用会不会令结余再次变负。NPV 衡量把未来的钱折到今天之后，是否覆盖投入。默认每年复用参考年产出形状并计算衰减，不是对未来每年天气的预测。

### 3. 最高可接受报价

NPV=0 时的总安装价等于折现后的运营净现金流。它是所选假设与折现率下的数学边界，**不是安装商应收价格或市场公允报价**。预算与持续回本目标还可能要求更低。业主用它理解自身条件，不用于指控承包商收费。

### 4. 最有深度的取舍

小容量与低前期投入、大容量与更多总发电；屋顶排布密度与相互遮挡；整体电价跨档与新增面板；投产日期与可获得的收入年期。存在更优配置并不取消 trade-off，应在可行前沿或受控 A/B 中解释最终冲突。

## 证据强度阶梯

1. 数学与软件核对：代码有没有按关系计算。已具备。
2. 参考计算流程对照：与另一流程的差异及原因。已具备；不能直接换算成实测准确率。
3. 独立气象输入对照：HKO 与 NASA。已具备 2025，但地点与时间基准不同。
4. 真实屋顶发电对照：有导入核对入口，没有实际取得的记录；保持未完成。
5. 用户使用观察：当前场景为设计假设；作为可选后续工作，未取得记录。

验证页的 PASS/FAIL/未核实会依照记录实际状态显示。报告如果缺少生成时间/指纹，或模型与数据发生变化，会标为未核实/过期，不把旧结果宣传成新版本已通过。

## 项目定位和广度建议

保留香港村屋业主这一个明确人群。业主关注的是方案是否符合自己的要求，而不是学会所有安装知识。让他们先理解三件事：收回投入的条件、多装面板的代价、输入偏乐观时是否改变选择。

已有空旷、遮挡、紧凑屋顶，以及不同预算、回本期限、投产日期和支架重量，足以展示广度。继续深入同一天台的选择变化、可复现依据和透明失败条件，比增加很多地区或设备更能服务这道题。

下一步若有条件取得数据，优先选择同一年、已知装机容量及几何的发电电表记录；不能把家庭购电账单当作光伏发电量。保留测量和模型输入，展示偏差并解释，不用一个案例宣称全部屋顶都准确。用户测试可记录是否看懂 A/B、回本和模拟边界，不能用“有问卷入口”代替完成访谈。
