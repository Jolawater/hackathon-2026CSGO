# RoofSun 2.3：先看需求，再比較方案

## 基礎與同步

在 `JESON-ROOFTOPJIM` 合入 Jim 的 `cadf2e2`，包含實際排數核對、候選排布去重、緊湊／展開排布、檢修間隙與村屋示例。沒有修改或覆蓋 Jim 的分支。後續更新需要再 fetch、審閱、合併和驗證，沒有背景自動監控。

## 用戶流程

1. 第一次進入先選「分析我的天台」或「先玩一個示例」。沒有選擇前不顯示假裝屬於用戶的回本數字。
2. 預算、每月電費單度數、希望匹配的年度比例放在主要區域。0 用電表示未知，不添加發電量要求；0 預算表示不限。
3. 天台方向、有蓋面積、支架重量等收進詳細設定。鄰屋遮擋提供窄樓／寬樓／一排樓的假設選項；角度仍可展開修改，沒有聲稱由文字描述精確測量。
4. 所有模型輸入先改草稿。「確認並保留」才改變計算與本機保存；「取消修改」恢復確認值。匯入 JSON 也是草稿，確認後才替換保存的比較方案。
5. 「根據你的條件，建議這樣裝」先摘要確認資料，再按優先目標顯示面板數、排數、方向、傾角、費用、年發電及回本日期。預設優先較快回本，可改為較低投入、較高發電或長期收益。
6. 相同實際排布的推薦卡合併，列出同時符合的目標，不為湊足卡片數捏造不同方案。選推薦先填草稿，仍需確認。

## 用電目標的意思

篩選條件為：`年發電量 >= 每月用電量 × 12 × 希望匹配的比例`。

這是年度能量比較，不是逐時自給率、離網供電保證或停電備用能力。仍沿用 Jim 的香港上網收益模型：不能把同一度電同時計入賣電收入和節省電費。用電目標只增加篩選條件，不憑空增加收入。沒有儲能、逐時家庭負載或逆變器離網模型。

## 3D 與一天時間線

- Three.js 本地依賴，拖動 360° 旋轉、縮放、俯視與尺寸開關。
- 面板直接使用後端 corners，避免另外畫一套不一致的排布。天台物件使用輸入的矩形尺寸。
- 可拖動整組面板，也可輸入 X/Y 位移；先填草稿，確認後檢查邊界與物件碰撞。所有排保持平行，維持現有排間遮擋模型的適用性。未實現任意單板方向及自由組串。
- 樓高是畫面選項；鄰樓是由天際遮擋角重建的近似輪廓，不是實測建築模型。高樓畫面不表示香港村屋規則適用於高樓。
- 選月份後以該月 15 日示意。`POST /api/sun-track` 一次向量化計算 97 個十五分鐘節點，以原有 pvlib NREL SPA 求太陽位置。前端只在顯示層插值。
- 0–24 小時可拖動、播放、暫停和調速，太陽標記、黃色光線箭頭、方向、陰影、日夜亮度同步更新。播放不重跑年度計算，不重建 WebGL 畫布，也不改已確認的財務方案。
- 後台重新計算時保留上一次完整場景，小提示標明正在更新。WebGL 不可用時退回靜態圖，不宣稱仍提供 3D。
- 渲染陰影與年度發電使用的幾何近似並非同一種求解器；沒有增加可驗證精度的聲稱。

## 模擬年限與地區

`analysis_years` 可選 1–25 年，實際改變收支期間、NPV、回本判定及推薦。沒有達到回本就顯示未達成。短期內「持續回本」只表示直到所選結束日沒有再次變負，不保證之後不會維修虧損。年度天氣重複所選歷史年，另按原模型加入衰減及成本，並非未來天氣預報。

物理方法可移植到其他地區，但當前定量結果仍是香港情景。北京、新加坡、倫敦等需要獨立逐時天氣、經緯度、時區、貨幣、電價／補償機制和建築限制。沒有僅靠城市選單把香港資料冒充當地預測。

## 比賽展示

先填預算與用電目標 → 確認 → 看一句話建議 → 比較另一方案的費用、發電與回本代價 → 3D 播放一天看遮擋 → 查看原理和已知關係驗證。

模型檢查、原模型對照與真實用戶驗證仍分開。這次修改沒有創造訪談、真實屋頂實測、真實安裝報價或滿分承諾。

## 驗證入口

- `python -m pytest -q`：含位移守恆、無效位置、期間、更換費時點、用電約束不重複收入、太陽軌跡對照。
- `python scripts/validate.py`：重建帶指紋的原有物理驗證報告。
- `npm run build`
- `npm run test:browser`：新的確認流程、去重、期間、時間線、WebGL、保存與手機布局測試。
- `node scripts/owner-browser-test.mjs`：證據頁 PASS/FAIL/未知/過期及錯誤处理。

舊 `scripts/browser-test.mjs` 保留 Jim 原有即改即算介面的測試記錄；2.3 的 npm/CI 入口改為 `interaction-browser-test.mjs`，不能把舊流程測試的歷史結果當作新版已驗收。
