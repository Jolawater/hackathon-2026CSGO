# RoofSun HK：比赛定位、要求对应与演示

依据：用户提供的《HacKU 2026 — Problem Statements》第 7–8 页，以及《HacKU 2026 Official Participant Handbook》第 8、10–14 页。2026-10-03 核对。以下是团队自查，不是主办方评分或资格认定。

## 问题与目标用户

**让不熟悉太阳能安装的香港村屋业主，在确认方案、投入金钱和屋顶空间之前，看懂方案是否符合自己的预算、空间和回本要求。**

业主会请安装师傅，但仍需要理解：同一个屋顶装多少块合适？增加投资换来多少发电？遮挡、10 kW 电价门槛和投产延迟会不会改变选择？不需要假定师傅收费过高，也不以取代现场勘察或专业设计为价值主张。

原型将“未知的安装结果”变为可以调整条件、保存 A/B 并解释选择的实验。结果可以是继续讨论某个方案、调整规模、询问报价范围，或暂缓安装。

当前用户画像和问题是设计假设。**没有声称已完成真实用户访谈或使用记录。**题目要求模型对照已知关系或参考案例，并没有把访谈、真实屋顶或硬件实验设为唯一验证方式。真实使用观察可支持更强的人本设计证据，但不是试用模拟器的前提。

## 必须满足的题目要求

| 要求 | 实现 | 展示证据 |
|---|---|---|
| 一个小物理系统 | 一个矩形屋顶上的固定式太阳能阵列 | 屋顶、板位、遮挡与负载的模型范围 |
| 至少两个输入 | 倾角、朝向、排数、面板上限、屋顶尺寸 | 调整控件，结果随计算更新 |
| 至少一个现实约束 | 屋顶边距、覆盖、预算及持续回本期限 | 不可行状态与拒绝推荐案例；结构部分仅为初步筛选 |
| 冲突结果 | 更多总发电与更高投资；更密排布可能增加遮挡 | 同条件排数 A/B、额外投资、单位容量产出 |
| 已知关系或参考案例验证并展示 | SPA 基准、遮挡几何、ModelChain、HKO 输入对照 | Model & sources 的结果、来源、时间和指纹状态 |
| 比较至少两个配置并说选哪个及原因 | A/B、按财务目标的候选、暂缓安装基准 | 演示者明确说明在所选偏好下为什么选 A 或 B |
| 明示模拟和遗漏 | 示例标识、工程假设、气象与财务边界 | 依据页、导出的决策报告 |

不是所有输入改变都会产生冲突。有些调整能同时省钱和增加发电，那是较差方案被改进。演示最终应比较不能同时改善所有目标的候选，或展示明确的受控排数实验。

## 展示轮：六项各 5 分

| 评分项 | 本项目可以展示什么 | 不应声称什么 |
|---|---|---|
| 问题与用户需求 | 业主理解安装方案的具体决定、预算和回本条件 | 没访谈却说需求已被真实用户验证 |
| 方案与人本设计 | 简单/进阶模式、三种业主问题、通俗结果、带给师傅的问题 | 仅凭页面好看就证明所有用户都易用 |
| 技术实现 | 小时级气象、排布、遮挡、财务门槛、约束筛选和失败处理 | 引用 pvlib 就等于原创太阳能算法或实测准确率 |
| 原型与展示 | 可运行、A/B、解释、导出和反例 | 只有源码就等于公开演示可用 |
| 创新与创造力 | 将本地条件、财务门槛与可解释取舍整合为业主决策流程 | 未调查就说世界首创或其他工具均无此功能 |
| 实用与影响 | 帮助明确下一步与方案讨论，能建议暂缓安装 | 保证节省某金额、保证回本或确认结构安全 |

## 路演轮：六项各 5 分

1. **问题相关性**：一个业主、一个安装决定，说明为什么只知道最大装机容量不够。
2. **市场/竞争理解**：比较安装报价、发电模型库和本项目各自用途。安装师傅提供现场设计施工；pvlib 等提供建模能力；本项目把条件、目标、比较和解释组织为业主可用流程。不要对未调查竞品作排他性断言。
3. **方案价值**：说明用户具体能决定什么，以及什么还要带给师傅确认。
4. **创新差异**：重点展示整体电价跨档、投产时间、收益目标导致的选择变化。
5. **表达结构**：一组 A/B、一个反例、一组验证；不逐个介绍所有控件。
6. **影响与未来**：拓展真实商业面板、站点数据和使用观察；说明它们是后续工作。

## 三分钟演示稿

### 0:00–0:25：为什么需要这个工具

“业主会请师傅安装，但确认之前仍想知道：这个方案是否符合我的预算和回本要求？RoofSun 让业主在花钱和占用屋顶之前，先探索两种选择。今天使用的是清楚标注的模拟天台。”

### 0:25–1:10：同一天台的 A/B

打开默认天台，确认气象年、报价和投产日期相同。保存两排与三排为 A/B。读出当前界面实际计算的发电与投资差异，解释单位装机产出及遮挡。不要引用旧版 HK$14,000/kW 产生的三年回本结果；当前默认报价已改变。

“我选择哪一个，取决于愿意投入多少，以及需要多少额外产出。更多发电不等于每个人都该选更多板。”设定一个明确预算或回本期限后，指出具体选择和理由。

### 1:10–1:45：决定为什么会改变

点业主说明中的“如果发电没有预期那么多”，说明 −15% 是人为压力情景，不是置信区间。比较当前报价与压力情景报价上限。或者演示 22/23 块跨越 10 kW 电价门槛：只有屋顶能放下时才使用这个案例，面板上限不是强制数量。

### 1:45–2:15：工具也会拒绝

将投产时间改为 2032 年，保持保守的 2033 年后无收入情景，运行推荐并解释暂缓安装的结果。恢复默认输入，避免把反例留作下一次演示的起点。

### 2:15–2:45：验证而非保证

打开 Model & sources，指出太阳位置基准、几何核对和参考发电流程。说明 HKO 是独立气象输入对照，不是本屋顶电表。验证报告显示时间、模型版本及输入指纹，过期报告不作为当前通过证据。

### 2:45–3:00：收尾

“我们帮助业主理解条件与取舍，带着更清楚的问题去确认安装方案。原型有工程与参考案例依据，尚未宣称现场准确率或完成用户调研。”

## Pitch Deck 内容提纲

1. 一句话问题与假设业主情景。
2. 确认安装前的决定：预算、空间、回本。
3. 模型输入—物理约束—输出图。
4. 一组实际运行的 A/B 及选择理由。
5. 来源与验证层级：物理/软件/气象/尚无现场发电验证。
6. 定位与替代方式比较、当前原型、可执行下一步。

这是一份可用于制作幻灯片的内容提纲，不代表最终 Pitch Deck 文件已完成。

## 深度与广度

**深度优先**：同天台的受控实验；离散面板数；10 kW 整体电价跨档；2033 截止与持续回本；敏感性是否改变决策；数据足够时给条件结论，不足时保留边界。

**广度来自不同约束**：空旷/遮挡/紧凑天台、预算紧/回本期限短、投产早/延后、锚固/压重假设。无需拓展到所有屋顶或所有能源系统。当前适用范围仍为项目声明的矩形村屋连续覆蓋情景，不自动推广到工商业屋顶。
